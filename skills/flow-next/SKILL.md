# 下一步建议

用户说「现在该做什么」「还差什么」「接下来呢」「怎么继续」，或含糊地停住时，先做这件事，不要改代码。

每个其他技能正常做完后，也要做一次。

## 怎么做

1. 工作区是 Cursor 打开的业务项目根目录，不是套件仓库。
2. 运行套件里的 `scripts/next.ps1 -Workspace <工作区>`（macOS 用 `scripts/next.sh`）。
3. 以工作区 `.cursor/next-step.txt` 为准（UTF-8）。控制台若是乱码，不要猜，读这个文件。
4. 回复里先原样列出文件中「步骤：」下面的每一行。若还有「开发进度：」，把那些任务行也原样列出，标了「当前这一条」的不要改成别的任务。本轮改过业务代码时，在步骤清单之后按 `skills/flow-implement/SKILL.md` 的「这一步怎么回复」写全六块，不要收成一两句。然后再写这五行，放在一起：
   - 套件进度：文件里的「套件进度」
   - 技能安装：先跑套件 `scripts/check.ps1`。通过就写「通过」。缺依赖就写名字，并说明挡不挡当前这一步。
   - 请你确认：当前需要用户点头的一件事。没有就写「无」。
   - 请你做：只有用户本人才能做的事。没有就写「无」。
   - 下一步：一句具体的动作。是用户做的，就写用户要发什么或点什么；是 Agent 接着做的，就写「我接下来会……」。每次回复都写，包括刚做完一步的时候。
5. 然后再做「下一步由你来做」。做完只把「请你确认」留成一个问题。不要把脚本原文交给用户复述。
5. 「下一步请用户定」：用自己的话问这个问题，然后停下。不要改代码来填这个空。
6. 「下一步就做这一句」只用于旧输出。新脚本不再靠用户把这句话发回来。
7. 「还可以稍后做」和「不挡住当前需求」不是当前这一步。不要把它们说成卡住了，也不要为此停掉正在做的需求。
8. 脚本指出被挡住或问题未确认时，不要改去写开发顺序或业务代码。
