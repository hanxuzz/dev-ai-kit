# 下一步建议

用户说「现在该做什么」「还差什么」「接下来呢」「怎么继续」，或含糊地停住时，先做这件事，不要改代码。

每个其他技能正常做完后，也要做一次，并把「下一步就做这一句」说给用户。

## 怎么做

1. 工作区是 Cursor 打开的业务项目根目录，不是套件仓库。
2. 运行套件里的 `scripts/next.ps1 -Workspace <工作区>`（macOS 用 `scripts/next.sh`）。
3. 以工作区 `.cursor/next-step.txt` 为准（UTF-8）。控制台若是乱码，不要猜，读这个文件。
4. 行首是「下一步就做这一句」时，把后面那句话告诉用户，用户可以照着发。
5. 行首是「下一步由你来做」时，不要把这句话交给用户。在本轮按它执行。规范未确认时，立刻按 `skills/flow-conventions/SKILL.md` 收集并提问，问完就停。不要预告后面的需求、文件名或开发步骤。
6. 「还可以稍后做」和「还可以优化」放在后面，不要抢在下一句前面让用户先去做优化。
7. 脚本指出被挡住或问题未确认时，不要改去写开发顺序或业务代码。
