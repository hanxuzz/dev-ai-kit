# 查看进度

优先运行 `kit assist resume --workspace <工作区>`，摘要包括已完成、进行中、代码变化与验证缺口。需要底层状态时才用 next 或 status --full。

默认只回复当前任务、刚完成的结果、阻塞（如果有）和下一动作。不要每次列所有依赖、完整步骤和五个固定标题。
对用户用口语。不要把 `kit` 命令、`--apply` 或阶段代号当成用户要做的事。命令只在内部执行。

输出 phase 是当前建议，不是权限：询问进度只读；执行一步只做本次授权的一步；连续执行只在用户明确授权的计划范围内推进。

- adopt：告诉用户先只看一眼、不改文件，原来的规格和计划留着，旧清单上的勾选不算做完。请用户回复「可以接管」。用户没点头就不要写入。不能要求缺状态的需求先通过普通校验。
- prepare/confirm：补足事实或确认版本，不能伪造确认。
- conventions：处理真实规范差异和当前分支，不反复询问已确认内容。
- blocked/questions：明确缺什么及谁能解决；其他不依赖的需求可以处理。
- test/accept：验证当前代码或等待用户验收，不能追加开发任务拖延收工。
- done：明确已结束，可选择下一条需求。

每个技能结束允许读一次 next，但不会因此自动进入下一项工作。
