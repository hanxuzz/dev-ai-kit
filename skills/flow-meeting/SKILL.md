# 会议与演示材料

按 [录屏解析协议](../../docs/recording-analysis.md) 处理。用户明确没有录像时标记 source skipped 并写原因，不继续索要；有录屏时发现并读取当前适用解析技能，优先复用本地 asr-watch 或等价能力，不假定固定路径和模型。

先转写/索引与少量代表帧，再针对指代、关键操作和疑点回看片段；需判断 UI 的结论必须查看画面。长片记录覆盖区间，局部补跑、复用有效缓存；不全量读取所有帧，不把稀疏抽样说成完整观看。

记录 M 编号、原时间、口述/画面依据、需求含义与未决事项，写 01-meeting.md。通过 prepare 更新来源和摘录；部分解析保持 pending，听不清、冲突或身份不明不猜测，只阻挡依赖这些决定的工作。明确用户决定和演示现状的区别，不把转写自动当已确认需求。

结束按 [进度反馈协议](../../docs/progress-feedback.md) 主动报告实际覆盖、结论、缺口及下一步。测试过程录像取证另见 [浏览器测试](../../docs/browser-testing.md#测试过程录像与-trace)。
