# 提交与推送

读取对应代码仓规则、team/conventions.md、当前任务状态和 Git 状态。工作区为多仓时进入用户指定仓库；单仓时使用配置的 app 路径。
用户没说提交就不 commit，没说推送就不 push；不 force、不绕过钩子、不改 Git 配置。

核对本次相关文件，排除凭证、本机 project.local.yaml、过程文件和未经授权的原件。不使用 git add . 扫入他人改动。
未决问题范围的业务改动不提交；规范要求本轮验证时先获取对应有效证据。分支策略与自动操作权限按 docs/conventions.md，不再使用 enabled=false 推断正确分支。
提交后报告仓库、提交摘要和是否推送；提交改变 HEAD 后，后续验收应重新读取证据状态，不假定历史结果仍有效。

本轮结束必须按 [进度反馈协议](../../docs/progress-feedback.md) 主动反馈最新结果、进度和具体下一步责任方；使用最新 progress，结合真实操作与本轮授权说明，不能仅报完成或要求用户自行查询。
