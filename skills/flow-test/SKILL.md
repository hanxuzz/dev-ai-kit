# 验证与收工

开始前按 [flow-project-context](../flow-project-context/SKILL.md) 主动核对本步骤依赖的项目事实，将核实结果应用到项目配置与材料；来源变化只复核受影响部分，不拿套件示例代替实际项目约定。

先用 assist review 定位未运行、失败、代码变化、命令变化或范围变化；只处理需要补充的证据。

通过 files.requirement 获取规格，不硬编码 04 文件名。cases.yaml 的每个 T 对应 R；测试方式依据实际覆盖能力。
优先项目已有单元、组件、接口和集成测试；少量重要旅程才用完整 E2E，不为每条业务验收搭建浏览器全链路。

用户或项目验收明确要求“打开浏览器/操作页面测试”时，必须按 [浏览器操作测试协议](../../docs/test-automation.md#用户明确要求浏览器操作测试) 发现并调用适用技能，实际打开可见浏览器、操作页面并记录结果；不能用 API、静态检查或无头执行替代。缺技能/工具时明确说明，不能声称完成。

自动项：确认 runtime.checks 的 argv、repo、cwd、超时及 requires。本轮用户授权执行后用 run。没有数据库依赖的命令不要求配置数据库；需要数据库时必须实际只读权限，不只信布尔值。
人工项：真实执行者完成步骤后，用 manual --target case:T1 --result passed/failed/blocked --by ... --note ... 记录环境和观察。任务级人工验收使用 task:TASK-1。

命令失败、超时、执行期间代码变化都不是通过。历史结果、旧代码和旧需求版本的结果不算本次验证。代码或配置变化后重跑受影响检查；默认按仓库内容判断；团队核实完整依赖后可配置 checks.inputs 缩小到相对 glob，必须包含测试、构建配置及锁文件。
输出默认仅保存失败分类及建议；需要排障可用 run --diagnostic-log 保存本机脱敏尾部日志。脱敏不保证识别所有秘密，分享前必须检查；不把日志复制到需求或证据说明。

所有任务完成、所有用例在当前代码通过后，next 显示 accept；用户明确验收结束才 complete。manual 未执行不能当作通过，不能用删除用例绕过门禁。

需要生成测试、导入测试人员任意格式文件、选择本地/dev 环境时，先按 [flow-testing](../flow-testing/SKILL.md) 解析、规范化与接入。新自动用例使用 JUnit 精确映射，跳过、缺失及重复结果不能算通过；dev 部署结果不代替本地实施证据。

验收需同时验证需求新增行为与 development.regression_cases 中保持原样的行为。测试断言从原始需求、正式用例及原行为得出，不仅照着新实现写。任务完成前还需 flow-code-review；不能以所有测试通过替代需求和项目适配审查。

本轮结束必须按 [进度反馈协议](../../docs/progress-feedback.md) 主动反馈最新结果、进度和具体下一步责任方；使用最新 progress，结合真实操作与本轮授权说明，不能仅报完成或要求用户自行查询。

测试发现需修复的 Bug 时，必须按 [修复与续测协议](../../docs/test-automation.md#测试发现缺陷后的修复与续测) 暂停测试推进，保留失败现场，转 flow-implement/flow-code-review 按需求和项目规范修复；本地相关服务真实重启并确认新代码就绪后，先复测失败用例和受影响回归，再继续剩余测试。已有范围内修复授权不重复询问；dev 必须核实修复已部署才能续测。

浏览器执行前读取 [效率与证据协议](../../docs/browser-testing.md)：复用隔离会话、读取局部页面状态、按条件等待、失效后重新定位；失败按停点复测，视频/trace 按需留证，不通过减少真实验收来提速。

按 [测试复用协议](../../docs/test-reuse.md) 先查项目已有测试代码、事实和执行经验，核对变化后复用有效方法，避免重复发现和导入；成功路径在已授权范围内沉淀回项目。用户明确要求重测必须真实执行，动态环境不能仅凭本地摘要复用结果。每轮反馈实际复用项、重新核实/执行项及原因。

按 [测试文字报告协议](../../docs/test-report.md)，本轮测试前记录实际起始时间；结束或中断时用 test-report --since ... --apply 保存 Markdown，补充真实浏览器操作、修复/重启/复测及未执行原因，回复附报告路径。历史复用与本轮执行分开，不为补报告重跑测试。
