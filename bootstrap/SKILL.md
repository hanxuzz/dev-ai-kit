# 安装或升级

1. 先找 DEV_AI_KIT、已有 project.local.yaml 的 kit.path、用户给的目录或工作区外的同级 dev-ai-kit。都没有才从 https://github.com/hanxuzz/dev-ai-kit 克隆到业务工作区外。不覆盖同名未知目录，不写个人机器路径到仓库。
2. 确认业务工作区和代码仓；支持单仓或包含多个代码仓的父目录，不强迫用户改变打开方式。
3. 按 docs/runtime.md 检查 Python、Git 和隔离环境依赖。用户已要求安装时可安装明确所需依赖；不额外下载 ASR 模型或浏览器插件。
4. 读取现有配置；文档默认优先独立文档库，其次已跟踪文档，或用户选定共享目录。已有选择不重复问，不私自迁移。
5. 用 install/upgrade 预览差异，确认没有覆盖业务材料后在已有授权下 --apply。自定义规则保留并提供候选；解释需合并的差异，不称为自动升级成功。
6. validate --config-only。只检查核心依赖，可选能力在实际使用时检查。
7. 必须执行 skills/flow-project-context/SKILL.md，主动读取项目规则、真实代码/配置/CI 和项目指向的资料。核实并应用当前需要的规范、启动、测试及环境信息，记录来源和配置绑定；未知项明确标记，不复制模板示例为项目事实。已明确内容复用，只澄清缺项与冲突。
8. 告诉用户生成文件、文档落点、可选缺项和下一动作。编辑器若不自动加载新规则，再提示新开对话；不把新开对话当成所有安装必须的仪式。

旧版需求通过 adopt 单独迁移，旧运行命令不能猜测转换。安装/升级失败按备份和恢复说明处理，不创建一套绕开门禁的平行配置。

开发质量流程新安装默认开启 development.require_contract。升级保留旧项目配置；在用户已授权接入新流程时主动补此字段为 true，并说明现有任务需补实际开发依据和审查，不自动重写代码。配置缺字段时必须说明仍处兼容模式，不能声称新检查点已生效。
