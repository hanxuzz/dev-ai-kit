# 0.3 产品取舍与待验证点

这一版让开发者表达工作意图，把任务编号、状态版本、文件映射交给 Agent。核心仍是本地 CLI 与技能，不新增网页或常驻服务。

| 分歧点 | 当前处理 | 边界 |
|---|---|---|
| 小修改是否重复确认 | 明确原始请求可同时提供范围确认和执行授权 | 由 Agent 记录真实依据，脚本不能识别用户身份或证明授权真实 |
| 是否自动判定轻量任务 | 少量文字修改用启发式推荐，已知风险升级 | Agent 仍须检查业务语义；不是可靠的自然语言分类器 |
| 变更后是否全重做 | 结构化变更按映射与传递依赖重开，保留无关工作 | 正文无法映射、全局约束变化或旧确认过期时整体复核 |
| 文字纠错是否走确认 | 明确 editorial、说明理由且结构不变可保留确认 | 需操作者核对语义，脚本不能保证同义；空白默认也不自动豁免 |
| 代码变化是否全重测 | 默认仓库指纹；完整依赖已知时支持 inputs | 漏配输入可能漏报，默认不为追求省时自动生成过滤器 |
| 失败是否保留原始日志 | 默认分类与建议，显式选项保存本机脱敏尾部 | 脱敏不完备；日志尾部可能缺上下文；不自动上传 |
| 验证到什么程度 | 临时 Git、真实文件与子进程覆盖关键开发旅程 | 不用大规模完整 E2E；尚无真实团队长期试用结果 |
| 是否统一成一个大技能 | 一个轻量意图入口，细节按需读取现有技能 | 自然语言路由依赖 Agent 执行能力，CLI 不是自主开发代理 |

上一版取舍保留在 [0.2 记录](decisions-0.2.md)。0.3 对选择性失效和日常入口的说明取代旧版对应条目。上线推广前仍建议用真实小修复、已有需求接管和中断恢复收集使用反馈；没有数据前不宣称降低了多少耗时或确认次数。
