# 依据、确认与权限

1. 业务仓 AGENTS.md、现有规则和已确认团队规范约束代码、分支与提交。收集时保留来源，不修改原文。
2. 已确认规格确定范围内、明确不做和验收。计划不能新增范围，原始设计不能默默扩大已确认范围。
3. 代码和接口是现状依据；原始工单、设计、截图是需求来源。二者与规格冲突时先澄清。
4. 结构化映射和脚本决定状态门禁；文件存在、模板已复制、口头「应该可以」不表示完成。

确认记录绑定材料、任务、用例和来源版本摘要。变更后复核范围并重新确认，不能只把一个布尔值改回 true。
用户可以一次授权一批明确任务；材料整理、业务执行、提交、推送、部署的授权分别判断，不能互相推导。

## 操作模式

| 用户意图 | Agent 行为 |
|----------|------------|
| 看看进度、下一步是什么 | 只读 next/status，解释当前状态 |
| 整理材料、接管旧需求 | 准备来源、映射、范围和待确认问题；不改业务代码 |
| 做一步、做某个任务 | 检查门禁后执行该任务、验证、报告，停止 |
| 按已确认计划连续执行 | 在本次明确授权范围内逐个做满足依赖的任务；遇到新范围、阻塞或需要确认时停 |

每个技能结束可读取 next，但读取结果不是下一次执行的授权。规则不要求用户复述脚本输出。

轻量路径也要有范围和验收；涉及视觉还原时必须查看设计原件，普通文案或字段修复可使用已确认文字和现有页面。缺少不相关工具不阻挡当前任务。

明确的小改动请求可以同时构成范围确认和执行授权，不要求额外重复确认；Agent 必须记录真实原话及确认者，脚本不提供身份认证。仅询问、建议或整理材料不能转换成执行授权。结构化变更只确认新增决定；已确认且未受影响的内容保留。
