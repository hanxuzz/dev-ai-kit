# 分层测试策略

本项目是开发流程套件，主要风险是文件、状态、Git 和命令之间的衔接；浏览器点击不是核心测试对象。
参考 [Practical Test Pyramid](https://martinfowler.com/articles/practical-test-pyramid.html)：不同粒度覆盖风险，越高层数量越少，避免重复验证。
隔离工作区沿用 [临时目录测试实践](https://docs.pytest.org/en/stable/how-to/tmp_path.html) 的原则；实现使用 Python 标准库 unittest/TemporaryDirectory，减少额外依赖。

## 层次

1. **快速规则测试**：路径边界、YAML 重复键、状态失效、依赖循环、版本冲突。
2. **流程集成测试（主体）**：真实临时目录、真实本地 Git、可控本地子进程，覆盖安装→接管→确认→任务→验证→收工，以及失败恢复。无需模型、账号或网络。
3. **少量入口冒烟**：CLI 退出码与输出协议，shell/PowerShell 参数传递和带空格路径。
4. **人工场景验收**：在真实编辑器检查模型是否按权限停下、设计是否看对、资料是否理解正确。自动测试不声称能证明这些语义。

不启动真实业务服务器，不连接真实数据库，不调用转写模型或浏览器账号。外部能力只检查前置和失败行为；业务项目已有的接口/组件测试应优先复用，只有重要跨系统旅程才补少量完整 E2E。

## 执行

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Windows 使用 `.venv\Scripts\python.exe`，同一测试集。
测试创建临时 Git 仓，不提交、不改用户 Git 配置，结束后删除临时目录。不会修改真实业务仓。
`.github/workflows/test.yml` 提供手动触发的多平台测试，不默认在 push 后运行。

## 必须保持的场景

- 无录像文字需求和既有 Spec 不改名接入。
- 旧目录无 status 可恢复，旧确认不自动继承。
- next 只读；用户未授权执行时不动代码。
- 已完成任务进入验收，再收工，不重新创建任务。
- 需求变化、代码变化、命令变化、失败结果使旧证据失效。
- 人工验收不依赖数据库或自动命令。
- 跨仓任务按依赖推进，错误分支和范围外修改阻止完成。
- 超时终止进程，不写原始敏感输出。
- 升级不覆盖自定义规则；回退不覆盖安装后的新修改。

不要用输出文案完全匹配来代替行为验证；增加测试应对应真实用户旅程或故障条件。

0.3 增加 tests/test_experience.py：轻量授权、只读恢复、局部变更保留工作、文字纠错边界、代码输入范围和本机失败诊断。使用真实临时 Git 工作区和子进程，不连接外部业务系统；这是局部集成旅程验证，不代表真实开发者可用性评测。

自动化接入测试使用 tests/test_testing.py 的临时回环 HTTP 服务（系统分配端口），覆盖任意原件来源追踪、CSV/YAML 规范化导入、未审阅草稿门禁、真实 HTTP 子进程、JUnit 跳过/失败/缺失/重复、环境绑定和 dev readiness。这里的 dev 配置也指向本机夹具，不访问真实 dev。Playwright 模板需要业务项目已有依赖和实际接口，本套件测试不声称已在业务环境运行该模板。

项目发现测试在 tests/test_discovery.py：只读且不执行脚本、不暴露候选正文、文件与配置绑定变化检测、推测不转为事实、动态来源要求复核、仅收集有限相关候选。脚本只检查可追踪性，无法替代 Agent 对项目内容的理解和实际核实。

开发质量 tests/test_quality.py 覆盖：缺开发依据阻止开工、需求/用例映射校验、参考变化、测试通过但缺审查、审查不代替测试、代码变化后审查失效、问题未解决和覆盖不足拒绝通过、quick 不伪造项目依据、新安装默认启用。旧流程夹具显式采用兼容模式，严格检查另行验证。
