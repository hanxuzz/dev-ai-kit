# 浏览器操作的效率与证据

遵循 [测试协议](test-automation.md#用户明确要求浏览器操作测试) 的真实可见页面要求；以下只优化执行方式，不降低验收标准。适用技能和工具的实际操作接口以本机已安装版本为准。

## 选择和初始化一次

优先复用当前环境可用且符合要求的浏览器技能/工具，不为同一轮验证混用多套控制器。记录实际技能、工具、版本、会话、目标环境和页面。已有工具满足要求时不安装新工具；新增选型可评估 Playwright CLI + Skills，需连续探索页面时也可用 Playwright MCP。CLI 默认可能无头，必须显式确认可见模式；不把安装成功当作能访问目标。

按项目/角色隔离会话，同轮复用已授权的测试登录态，不每条用例重新启动浏览器。需要干净状态的用例使用独立上下文或准确恢复前置，不混用不同角色或污染用例数据。状态文件可能含凭证，仅留本机忽略目录；不读取、输出或共享完整登录态。

## 小步观察，按条件等待

- 普通表单交互优先可访问性快照、角色/标签和最新元素引用；工具支持时查询局部区域、交互元素或快照差异，避免每步输出整页。布局、画布、拖拽或视觉错误按需截图/视觉定位，遵守该工具协议，不强行使用它不支持的定位方式。
- 导航、重新加载、重启服务或引用失效后重新读取页面；定位失败先更新观察，不猜元素引用或盲点坐标。沉淀脚本使用语义定位或项目稳定 test id，避免长 CSS/XPath。
- 使用工具支持的可操作性等待和有超时的条件断言：等待目标可见、可点击、加载消失、业务结果出现；不以固定 sleep 或仅等待 network idle 判定成功，不用强制点击绕过遮挡问题。
- 当前页面已观察且稳定、无业务分支的连续输入可使用工具支持的批量表单操作；提交、导航、弹窗和状态变化后先观察，再决定下一步。失败即停止当前操作序列，不预先排队依赖未知结果的点击。
- 快照/截图差异帮助定位变化，业务通过仍依据原需求和实际断言；页面没变化或 HTTP 200 本身不代表通过。

## 修复后的快速恢复

遵循 [修复与续测协议](test-automation.md#测试发现缺陷后的修复与续测)。暂停时记录失败用例、页面、必要前置和待执行用例。修复后重启受影响的本地服务并确认新代码就绪；通常保留浏览器会话，重新加载页面并获取新定位。涉及认证、缓存、会话或数据污染时重新初始化相应状态。

先复测失败项和受影响回归，再按停点继续。只有能说明依赖边界时才缩小回归范围；公共组件、配置或依赖变化需扩大验证。页面取证可局部，套件证据失效范围仍按实际配置执行，不能把旧 passed 手工搬到新版本。

## 测试过程录像与 trace

需求会议录像是输入材料，见 [录屏解析](recording-analysis.md)；本节是测试证据。不是每步都录像：关键页面保留必要截图，复杂交互/时序问题按需在复现前启用 trace；用户要求录像时从目标场景开始前启动实际录像，记录结束后检查文件存在、可读取及覆盖的用例/时间段。不得把操作日志或截图冒充视频。

使用已有工具支持的录制方式，确认它记录的是画面视频还是动作脚本。Playwright Test 可按项目需求使用失败保留策略；不要靠无条件重试掩盖首次失败。视频需要对应浏览器上下文关闭后才写完时，只关闭本次拥有的上下文，等待落盘；工具提供停止录制时按其协议结束。不要为保存录像关闭用户其他浏览器会话。

trace/视频可含请求、账号、个人信息，默认本机受控目录，分享前检查；停止录制后仍须逐条报告业务结果。记录初次失败与修复后成功分别属于哪个版本，不覆盖首次证据。必要材料归档后才按项目保留策略清理本次临时文件，未结束排障不删除续测依据。

## 官方依据与验证边界

2026-10-12 核对：[Playwright CLI + Skills](https://github.com/microsoft/playwright-cli)、[Playwright MCP](https://github.com/microsoft/playwright-mcp)、[定位](https://playwright.dev/docs/locators)、[自动等待](https://playwright.dev/docs/actionability)、[trace](https://playwright.dev/docs/trace-viewer)、[录像](https://playwright.dev/docs/videos)、[agent-browser 差异](https://agent-browser.dev/diffing)。能力需以本机版本核实，不能假定所有工具都有同名命令。

本协议不承诺固定提速比例。在业务项目对相同用例记录用时、工具调用次数、失败重试和覆盖结果，再判断是否更快；缺少真实运行不能声称性能已验证。
