# 0.2 优化取舍记录

历史记录；当前选择性失效与产品入口见 [0.3 取舍](decisions-0.3.md)。

用户授权遇到分歧先按实现者判断处理，完成后报告。以下都是设计选择，不是用户已明确选定的长期偏好。

| 分歧 | 本轮选择 | 原因与代价 |
|------|----------|------------|
| 保留 PowerShell 核心还是统一运行时 | Python 3.10+、PyYAML，保留旧入口适配 | 减少重复门禁和手写解析；增加 Python 依赖，Windows 需准备环境 |
| Markdown 还是结构化状态 | Markdown 解释业务，YAML 管映射和状态 | 可校验覆盖、依赖和证据；Agent 需维护两者一致，不能自动证明语义一致 |
| 快速任务是否走全套文档 | quick 使用一份 brief，保留最小 R/TASK/T | 降低人类负担，不取消范围和验收 |
| next 是否自动执行 | next 永远只读；执行模式由用户本轮意图决定 | 避免看进度触发改代码；连续执行仍可由已授权 Agent 编排 |
| 变更后如何失效 | 保守重开当前需求所有任务、失效旧证据 | 避免漏测；当前未做精细影响传播，确认无关项也需重新核验 |
| 测试是否追求完整 E2E | 主要做本地流程集成、少量入口与快速规则测试 | 不依赖外部账号和模型；实际编辑器与连接器仍需人工场景验证 |
| 没有自动化是否能完成 | 允许有明确条件、实际执行人的人工验收 | 支持真实团队现状；不能靠文字记录伪装已执行 |
| 多人并发做到什么程度 | revision + 工作区/共享目录锁 | 支持同一可见文件系统；异步同步盘离线多写不保证一致，要求单写者 |
| 是否保留原始命令日志 | 默认只保存退出码、指纹和输出摘要 | 防止意外泄密；失败排查需授权查看/复现并脱敏 |
| 是否自动升级用户规则 | 只替换摘要匹配的已管理规则，其他提供候选 | 保护项目约定；自定义规则需要合并审核 |
| 是否自动启动服务/建分支/部署 | 核心只验证前置，Agent 按用户授权处理 | 不扩大权限；没有把 CLI 做成完整开发环境管理器 |
| 已有背景模板是否算完成 | 模板不算，Agent 明确起草并保留确认状态 | 不用文件存在代替内容；背景不足不阻止独立明确的小任务 |

## 不能承诺的能力

脚本不能证明需求理解正确、检查命令覆盖了业务验收、操作者身份真实、数据库实际只读，或远程设计未变化。这些需要 Agent 阅读、真实工具结果和团队确认。配置与证据是辅助机制，不是权限系统或强制沙箱。

旧配置迁移只在显式 --migrate-config 时重写，保留旧字段但不保留 YAML 注释格式，安装备份保存原文；宁可要求核对旧命令，也不自动猜测 shell 和执行目录。
