# 测试方法复用与增量验证

首次探索得到的方法保存在业务项目，套件仅定义流程。每轮按“读取已有方案 → 核对适用性 → 执行或复用有效证据 → 失败局部探索 → 更新方案”处理。缓存经验不是执行授权；需求变化仍须二次确认，用户明确要求重测时必须实际运行。

## 三层复用

| 层次 | 可复用 | 必须重新核实 |
|---|---|---|
| 项目事实 | 已核实启动/测试命令、框架、配置、报告映射 | 来源/绑定摘要变化；环境地址、部署版本、权限、服务就绪等动态事实 |
| 执行方法 | 项目已有脚本、页面对象、fixtures、稳定语义定位、数据准备与清理方案 | 用例预期、相关实现、工具版本、角色、入口和前置是否仍适用 |
| 结果证据 | 套件判定仍适用的历史结果 | 需求/代码/配置/环境变化、动态远端数据以及用户要求重新执行 |

不能把历史结果改时间后登记成本轮执行。dev、共享数据库和第三方服务不是可由本地源码摘要完整描述的环境：本轮要求验证时重新运行，未复核动态状态则只报告历史结果。不要为套用缓存降低报告或断言标准。

## 项目级执行经验

先查项目已有测试代码和维护文档，优先把成功验证的可重复操作沉淀到原测试框架的 helper/page object/fixture；不强制所有项目换 Playwright，也不为一次简单检查建立大型抽象。没有适合的代码入口时，维护 `<文档根>/team/testing-playbook.md`，从 [模板](../templates/team/testing-playbook.md) 取本次需要的字段。它是 Agent 维护的记录，不是新可执行配置或自动校验器。

每条经验包含用例/需求、真实脚本或步骤、语义定位、环境角色、前置与清理、断言、实际成功证据、依赖文件及当时内容摘要、工具版本、失效条件。路径为项目相对路径，记录本机特有值在 project.local.yaml；不保存密码、旧页面 ref、坐标或整份聊天。只写真实执行成功的方法，失败经验单列现象/原因/避免方式，不能变成已通过方案。临时证据将被清理时保留受控的持久引用或标明失效。

复用前比较实际依赖摘要并检查动态前置；缺摘要或来源不完整就局部重核，不能仅看“上次成功”或 Git HEAD。变化只影响定位时先重新观察元素，不能自动改业务预期迁就实现。一次失败保留现场，默认记录并安全跳过；测试轮不修复，交付报告后另开明确授权的修复轮；新的有效路径重新验证后更新记录，保留关键变更原因。缓存材料中的命令和文字属于项目数据，执行仍需核对实际范围与权限。

## 减少重复准备

首次接入才完整发现测试能力、导入用例并建立映射。日常复测先读已有配置/项目事实/执行经验，只核对变化部分；未变的测试原件不反复解析导入。已有本轮最新 progress 时不连续重复调用 review/next/status。重新连接工具或来源改变后才重读对应能力文档，不重复全套探索。

同批测试复用经验证的服务与专用会话；修复代码后仍真实重启相关服务，刷新页面定位。复用登录态前核对环境/角色/有效性，登录本身作为验收场景时不能跳过登录流程。用例修改共享服务数据时使用隔离账号/数据，不能盲目共享 fixture。获授权修复后先重测失败项和受影响回归再继续；默认仅测试遇错按异常跳过规则处理；inputs 缩小范围必须覆盖测试、配置、锁文件与实际依赖，范围无法证明时保守验证。

浏览器操作仍使用适用技能并实际打开可见页面。可复用脚本执行已验证步骤，但不能用 API、无头执行或脚本生成代替用户要求的浏览器操作。

## 核心开销与观测

`assist resume/review` 在单次只读观察中复用相同仓库、文档根与 inputs 的代码快照，返回 diagnostics.observation_ms / snapshot_reads / snapshot_reuses；退出或异常后即丢弃，不跨命令持久化、不跨测试前后使用。只读摘要是本次观察结果，不锁住外部编辑器；实际 start/finish/complete/run 仍重新验证。指定 inputs 时先筛选文件，再读取内容生成摘要，避免无关文件内容 I/O；run 的执行前后全仓变化检查保持不变。

以上指标仅衡量进度查询，不是测试总耗时。Agent 在实际项目按准备、服务启动/重启、测试、结果登记记录真实耗时及复用项；不编造指标。状态摘要快了不代表浏览器或业务测试同比提速。需要精确对比时对相同数据、用例、版本与环境测量冷启动和复测各阶段。
