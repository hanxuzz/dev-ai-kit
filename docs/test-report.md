# 每轮测试文字报告

测试技能每轮执行结束、失败中断或遇到阻塞，都要在需求目录保存 Markdown 报告并给用户可点击路径。用户不必单独要求，也不需要填写报告；明确只读或禁止写文档时只预览。报告不是验收授权，不能代替真实执行证据。

## 生成

测试开始前由 Agent 记录带时区的 ISO 起始时间。完成或中断本轮测试后使用：

```text
kit test-report --workspace <工作区> --id <需求号> --since <本轮起始时间> --apply
```

默认只返回 Markdown 预览；--apply 保存到 `<需求目录>/.kit/test-reports/<独立编号>.md`，每次生成保留独立文件，不覆盖旧报告。返回 path 可直接链接给用户。不会改变 status revision、确认、任务或验收状态，也不会重新执行测试。报告与证据按项目文档存储模式管理，不自动 commit/push。

起始时间必须来自真实记录，不能为了显得测过更多而回溯。中断恢复时复用已记录起点；没有起点则明确生成的是历史区间报告，不称为本轮。多需求分别生成。没有需求状态时不能伪造状态来生成，按下述结构写本轮实际测试记录到项目已约定的测试文档位置。

## 报告内容

自动汇总包括需求、区间、状态版本、阶段、当前定义用例清单、需求映射、预期、执行方式、证据记录的环境/部署版本、结果序列、当前有效性、本轮执行记录及下一步。用例被删改后仍保留区间内原始执行目标与证据编号，不将当前预期冒充旧执行时的规格。

- 失败后复测通过同时保留两次记录，不能只写最终成功。
- 有关联检查记录不等于每个用例实际执行：JUnit 跳过/缺失/重复映射单独显示；旧命令级用例明确不代表逐条断言。
- 过期 passed 与当前有效 passed 分开；本轮没跑但历史适用写明历史证据，不能冒充本轮重测。
- 未配置环境显示未记录，不猜 local/dev。观察型用例的实际环境由 Agent 从真实执行补充，不能由脚本推断。
- 报告保存的是生成时快照；后续代码/需求变化可能使证据失效。检查新状态需要读取最新进度。

## 整体报告交付（必填）

生成的 Markdown 是整体入口与待补充草稿，不是完整报告。Agent 按真实操作补齐以下部分，可在同目录放附件并从入口链接：

1. **总结报告**：环境/部署版本、时间、范围、逐条通过/失败/阻塞/跳过/未执行数量、主要风险、停止原因、后续建议；检查级结果不能冒充每条通过。
2. **最原始用例**：保留用户原始文件的受控引用或获允许保存的原件，核对原件哈希；每条映射原始编号、文件/页/表行、规范化编号与执行结果。生成器输出当前定义已有的 origin/source_location，不自动扫描或复制原件。原件不可访问、未解析、未导入或被删改的项单列缺口，不能把规范化文件当原件。AI 生成用例注明生成来源。
3. **具体操作步骤**：逐条写实际前置、页面、操作顺序、时间、预期与实际、结果、证据和未执行原因；不能粘贴计划步骤冒充执行日志。
4. **全程录像**：浏览器测试从首个操作前录到本轮结束，成功和失败场景都保留；每段文件、会话、起止时间、覆盖用例及中断缺口可追溯。停止后核对落盘、可播放、覆盖范围。纯单元/API 注明不适用。
5. **问题截图与分析**：发现问题立即截图；关联问题号、用例、录像文件和本段相对时间。给出复现、影响、模块及前端/后端/接口契约/数据/环境归属、依据和待验证方法。已验证原因与推测分开，证据不足写未知；只读分析，不修改代码或配置。
6. **完整性检查**：用原件总数核对导入、遗漏和全部执行状态，验证每个附件引用可用。缺录像、截图、原件或实际观察时保留缺口和原因，不能宣称完整交付或整体验收通过。

测试轮不修复。若用户要修复，先保存本轮报告，再单独进入明确授权的开发修复轮；修复后的新测试报告关联原问题并保留首次失败证据。

截图、视频和原件存于项目受控位置，分享前检查；敏感原件保留受控引用，不复制密码、令牌或客户数据进报告。Python 命令只汇总已登记证据与来源索引，不会代替浏览器/录屏技能，不会自动证明视频覆盖或原因归属。

每轮回复提供整体报告入口，简述通过/失败/未执行情况、证据完整性及下一步。生成失败时保留原证据并说明原因，不为补报告重跑测试。
